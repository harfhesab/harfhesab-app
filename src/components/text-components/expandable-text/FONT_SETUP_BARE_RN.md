راهنمای فونت سفارشی در React Native خام (بدون Expo)
======================================================

نکته‌ی مهم: در React Native خام (بدون Expo)، فونت‌های سفارشی برخلاف Expo
به‌صورت داینامیک/async لود نمی‌شوند. آن‌ها در زمانِ build به‌صورت فایل native
داخلِ اپ package می‌شوند (iOS: Info.plist + بسته‌شدن در bundle، Android:
android/app/src/main/assets/fonts) و از همان اولین رندر به‌طور کامل و
synchronous در دسترس‌اند. یعنی «لود دیرهنگام فونت» اصلاً نباید در پروژه‌ی
شما اتفاق بیفتد، به شرطی که فونت درست لینک شده باشد.

اگر همچنان مشکلی با فونت مشاهده می‌کنید (نه تاخیرِ اندازه‌گیری، بلکه خودِ
فونت درست نمایش داده نمی‌شود)، این‌ها را چک کنید:

۱) ساختار پوشه‌ها
------------------
یک پوشه در ریشه‌ی پروژه بسازید (مثلا assets/fonts) و فایل‌های .ttf/.otf را
آنجا بگذارید:

    project-root/
      assets/
        fonts/
          YekanBakhFaNum-SemiBold.ttf

۲) معرفی فونت به react-native.config.js
------------------------------------------
در ریشه‌ی پروژه (اگر فایل react-native.config.js وجود ندارد، بسازیدش):

    module.exports = {
      assets: ['./assets/fonts/'],
    };

۳) لینک‌کردن (فقط یک بار لازم است، بعد از هر تغییر در فونت‌ها هم دوباره لازم می‌شود)
--------------------------------------------------------------------------
    npx react-native-asset

این دستور فایل‌های فونت را به‌صورت native در iOS (Info.plist +
Copy Bundle Resources) و Android (android/app/src/main/assets/fonts) کپی
و رجیستر می‌کند. بعد از اجرا:

    - iOS: باید pod install دوباره اجرا شود (cd ios && pod install)
    - Android: پروژه را rebuild کنید (نه فقط reload؛ npx react-native run-android)

۴) استفاده در کد
------------------
فقط نامِ خودِ فونت (نه نام فایل) استفاده می‌شود؛ نام دقیق را می‌توانید با
باز کردنِ فایلِ فونت در Font Book (مک) یا هر ابزار مشابه پیدا کنید:

    textStyle={{ fontFamily: 'YekanBakhFaNum-SemiBold', fontSize: 12, lineHeight: 24 }}

روی iOS معمولا باید نامِ داخلیِ فونت (PostScript name) استفاده شود که گاهی
با نامِ فایل فرق دارد؛ روی Android معمولا همان نامِ فایل (بدون پسوند) کار
می‌کند. اگر فونت به‌درستی لینک شده باشد ولی نام اشتباه باشد، معمولا با یک
فونتِ fallback (نه فونت سفارشی، ولی هنوز هم فوری و بدون تاخیر) رندر
می‌شود — نه اینکه دیر لود شود.

نتیجه
------
اگر مراحل بالا درست انجام شده باشند، هیچ preload یا splash-gate جداگانه‌ای
برای فونت لازم نیست؛ فونت از همان اولین فریم در دسترس است. تاخیر/پرشی که
قبلا مشاهده می‌کردید ربطی به لود فونت نداشت — به تعداد رفت‌وبرگشت‌های
اندازه‌گیریِ متن در خودِ کامپوننت مربوط بود که در نسخه‌ی جدید ExpandableText
به یک رفت‌وبرگشتِ سبک در هر آیتم کاهش پیدا کرده است.
